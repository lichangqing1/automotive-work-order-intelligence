# C1 security release gate

Assessment date: 2026-11-12
Reviewed application commit: `70dcb9b25d101b0168ab361193326acda6349b53`

## Decision

The C1.6.1 application-level duplicate-execution P1 is **CLOSED within the
tested guarantees**. Durable operation claims, payload conflict detection,
successful response replay, lease-loss transition to `AMBIGUOUS`, blocked
automatic re-execution, principal-scoped status recovery, and stale-owner
protection have been verified. This is not a claim of exactly-once external
provider execution or billing across arbitrary crashes.

| Deployment target | Decision |
|---|---|
| Local development | GO |
| Isolated engineering verification | GO |
| Controlled staging with synthetic providers | CONDITIONAL GO |
| Shared deployment | NO-GO |
| Production deployment | NO-GO |

The shared and production decisions remain NO-GO because production Redis
authentication, TLS, high availability, failover and monitoring; application
TLS termination; secret-manager delivery and rotation; PostgreSQL and Redis
network isolation; reverse-proxy request limits; backup recovery; and security
event retention and alerting have not been verified in a deployment. Localhost
or GitHub Actions service containers do not prove those operational controls.

## Verification evidence

The C1.6 reassessment verified the final migration from an empty PostgreSQL
database through revision `20261112_0006`, including operation-state,
completion-timestamp, successful-response, composite-uniqueness, foreign-key,
and review-to-operation uniqueness constraints. The disposable verification
database was retained rather than deleted.

Current CI provisions ephemeral PostgreSQL and Redis services. Required
infrastructure selections are run explicitly and their JUnit summaries are
checked for a nonzero test count and zero failures, errors, or skips:

```text
pytest -m postgres --junitxml=postgres-integration.xml -q
pytest -m redis --junitxml=redis-integration.xml -q
pytest --cov=automotive_quality --cov=automotive --cov-report=term-missing -q
```

The Redis selection includes the PostgreSQL-backed AI lease-loss test, so the
CI quality job supplies both services and migrates PostgreSQL before either
required selection. Redis tests use per-test random namespaces in logical
database 15 and remove only their own keys; they never flush Redis.
